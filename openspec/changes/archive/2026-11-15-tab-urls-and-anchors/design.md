## Decisions

Request, from the project lead: "The tabs should have `/proposals` and such in the URL for other tabs. Each section should have anchor links." The numbered choices below are the design decisions that followed.

- **Path is the tab, from one table.** `src/lib/route.ts` holds a table of tab ids and labels and derives each path from the id (`map` is `/`). The same table answers path to tab and tab to path. Case and trailing slashes are ignored on the way in, and `/index.html` is the Map.
- **Tabs are `<a href>`.** A plain click calls `history.pushState`; a modified click or a click with another button is left to the browser, so open-in-new-tab and copy-link work. `aria-current="page"` marks the current tab. Focus stays on the clicked link, as it did on the button.
- **Two kinds of fragment.** `#v1` or `#v1;…` is a scenario. Anything else is an anchor. Scenario decoders only ever see a scenario fragment, so an anchor is never reported as an unreadable link. The skip link no longer changes the fragment: it moves focus to `main` itself.
- **The scenario is never dropped.** Switching tabs writes the scenario fragment on the new path whenever a scenario exists. Following an anchor link replaces the fragment with the anchor; the scenario stays in app state. It returns to the address when the person goes to a tab without an anchor, or changes the scenario. Opening a URL whose fragment is an anchor starts with no scenario, as a URL with no fragment does.
- **Back and Forward.** A history step to another tab, or off an anchor, does not read the old entry's scenario: the entry can predate edits, and the app's state is the truth. Only a fragment change on the same tab with no anchor showing is read as a new scenario, as before. A `hashchange` that follows such a step is skipped by matching its new URL.
- **Anchor on cold load.** Sections render lazily and after data loads, so `scrollToAnchor` waits for the element with a mutation observer (up to 20 s), scrolls it to the top of its scroller (smooth unless the person prefers reduced motion), and focuses the heading (`tabindex="-1"`). For 6 s it checks every 250 ms and, when the page is idle and the heading has moved off its place because layout above it changed, scrolls it back. Wheel, touch, key and pointer input stops it so it never fights the reader.
- **Ids.** The slug of the heading or a data id, unique per page, stable across reloads and data rebuilds: `proposals`, a group's id, `<group>-<proposal id>`, `assumptions`, `assumed-movement-flows`, `move-<movement id>`, `why-cars-cut-through`, `reason-<reason id>`, `sources`, `calibration`, `data-provenance`, `research-references`, the citation key, the slug of each bibliography heading, `streets`. Old ids (`ref-intents`, `ref-movements`, `ref-calibration`, `ref-<key>`) are rewritten to the new ones when a URL carries them.
- **Anchor control.** A 24 by 24 CSS px link (`<a href>` to the section, so it can also be copied or opened in a tab) with the name "Link to this section: <heading>". It is invisible until the heading is hovered or the control is focused, always visible when the device has no hover, and takes its space whether shown or not, so nothing shifts. A click pushes the anchor URL, copies the full address, announces "Link copied" in the polite status region and shows the same words beside the control for two seconds. It does not scroll: the heading is already in view.
- **Scroll offset.** Headings carry `scroll-margin-top` so a heading is never flush against, or under, a sticky table header or the top bar.
- **Server.** `run_worker_first` lists only `/api/*` and `/data/*`, and `not_found_handling` is `single-page-application`, so `/proposals` and the other tab paths already get the app shell with status 200. We kept that for unknown paths too: they get the app shell, and the app shows the Map and corrects the address. A real 404 for unknown paths would need the Worker to run first for every request or a list of asset paths to maintain; the app's own correction is cheaper and a person who mistypes still lands somewhere useful. The test reads `wrangler.jsonc` so a change to either setting fails it. `/data` and `/api` behavior is unchanged: a missing data file is still a 404 JSON body. The Vite dev server falls back to `index.html` for the same paths.
- **Document title.** `<Tab> · Traffic: <area name>`, set on every tab change.

## Not changed

Stored-result keys depend on the canonical scenario and the period only, never the URL, so they are unaffected. The proposal image's QR code and short URL still point at `/` plus the scenario fragment.
