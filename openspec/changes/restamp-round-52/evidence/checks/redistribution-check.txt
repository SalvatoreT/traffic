Cause: tools/precompute-redistribution.ts:120 keeps, for each street label, the first route sample it receives (if (!a.samples.has(x)) a.samples.set(x, l)), and the seeds run in a worker pool, so the sample comes from whichever seed finishes first. A faster simulator changes that order.
Check on the new binary, p1 only (npm run data:redistribution -- --only p1 --force):
- --jobs 8, second run: identical to the first --jobs 8 run (all fields; computed timestamp aside). Same links: 24 of 24 routes.
- --jobs 1 (seeds in order): same links as the --jobs 8 run for 18 of 24 routes; same links as the published file for 18 of 24 routes. Non-link fields identical to the published file: true.
So the drawn path of a route depends on how the seeds are scheduled, not on the simulator. The p1 file in public/data is the first --jobs 8 run (put back after the check).
